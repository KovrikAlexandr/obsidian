```bash
sudo ip addr add 192.168.65.5/24 dev enp0s1

```

Установка nmcli и dhclient
```bash
sudo apt install isc-dhcp-client network-manager
```

## Network-Manager (nmcli)

Создать статически:
```bash
sudo nmcli con add \
con-name "static-con" \
ifname enp0s1 \
type ethernet \
ipv4.address 192.168.1.100/24 \
ipv4.gateway 192.168.1.1 \
ipv4.dns 8.8.8.8
```

Динамически:
```bash
sudo nmcli con add \
con-name "dynamic" \
ifname enp0s1 \
type ethernet \
autoconnect yes
```

## Проблемы виртуальных машин и netplan
Если создать клон ВМ, то может сломаться dhcp в shared network.

Если для конфигурации сети используется netplan, то по умолчанию для формирования client id в dchp запросе подставляется `/etc/machine-id`

Есть два способа этого избежать (лучше делать вместе)
### 1. Настроить netplan
Чтобы использовать для client id не machine-id, а MAC адрес:
```yml
network:
  version: 2
  ethernets:
    enp0s1:
      dhcp4: true
      dhcp-identifier: mac
```
- `dhcp-identifier: mac` решает проблему

### 2. Поменять machine-id
Делаем так:
```bash
sudo rm /etc/machine-id
sudo systemd-machine-id-setup
```
