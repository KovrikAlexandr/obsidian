Три группы прав:
- u (user) – владелец файла
- g (group) – группа
- o (other) – все остальные
В каждой группе права:
- read
- write
- execute

Права по умолчанию:
- Для файлов – 644
- Для директорий – 755
Изменить поведение можно через [Umask](obsidian://open?vault=obsidian&file=public%2F%D0%97%D0%B0%D0%BC%D0%B5%D1%82%D0%BA%D0%B8%2FLinux%2FModes%2FUmask)

### Файлы
Права:
- `read` (4) – чтение
- `write` (2) – запись
- `execute` (1) – исполнение
##### Пример:
```bash
$ ls -lh /opt/nginx/nginx.conf
-rw-r--r-- 1 root docker 20K Jan 13 10:50 /opt/nginx/nginx.conf
```
- Владелец (user) – `root`
- Группа (group) – `group`

### Директории
Права:
- `read` (4):
	- Просмотр директории (`ls`)
	- Не влияет на вложенные директории
- `write` (2):
	- Удаление директории
	- Создание новых файлов в директории
	- Не влияет на изменение существующих файлов
- `execute` (1):
	- Переход в директорию (`cd`)
	- Влияет на переход во вложенные директории

## Расширенные права

### SUID (Set UID)
Используется для исполняемых файлов.
Файл будет исполняться от лица owner, неважно, кто его запускает.

Выдать SUID (4):
```bash
sudo chmod u+s test.sh
```

По факту это здоровенная дырень в безопасности и часто эта возможность отключена в системе.
