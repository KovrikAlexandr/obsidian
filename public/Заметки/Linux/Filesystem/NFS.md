NFS (Network FileSystem) – протокол, который позволяет использовать удалённую файловую систему так, будто она локальная

В этой системе есть:
- **Сервер** – тот, кто настраивает экспорт каталогов. Задаётся в конфиге `/etc/exports`
- **Клиент** – тот, кто пользуется удалёнными каталогами. Для получения доступа клиент просто монтирует каталог через `mount`.

Установка NFS на Ubuntu:
```bash
# For server
sudo apt install -y nfs-kernel-server
sudo systemctl enable nfs-server
sudo systemctl start nfs-server

# For client
sudo apt install nfs-common
```

## Конфигурация сервера

Набор экспортируемых каталогов и правила доступа к ним настраиваются через `/etc/exports`.

После внесения изменений применить настройки можно так:
```bash
sudo exportfs -ra
```

### Формат файла

Каждая запись (строка) – один каталог и его настройки.
Формат записи такой:
```
/path/to/dir client1(opt1,opt2) client2(opt2,opt3)
```

#### Client
Поле `client` маппится с тем, кто монтирует себе этот каталог. 
Может содержать разные значения:
- `hostname.example.ru` – имя домена
	Сервер должен уметь разрешить это имя через reverse DNS lookup
- `192.168.1.10` – IP адрес
- `192.168.1.0/24` – сеть в CIDR нотации
- `*.example.ru` – поддомен
- `*` – любой клиент
### Опции конфигурации

**sync/async**
- **sync** – клиент дожидается ответа от сервера после изменений
- **async** – клиент не ждет ответа об изменениях. (Типо быстрее, но опасно, не надо это использовать)

**subtree_check/no_subtree_check**
Какая-то legacy проверка. Ставим **no_subtree_check** и не паримся

## Клиент
Можно получить список экспортируемых сервером каталогов:
```bash
showmount -e <server ip>
```

Смонтировать:
```bash
sudo mount -t nfs <server ip>:/path/to/remote /path/to/local
```
