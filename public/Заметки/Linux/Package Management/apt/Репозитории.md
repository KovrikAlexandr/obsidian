Debian/Ubuntu репозитории это HTTP/HTTPS/FILE сервер, на котором хранится структура каталогов и индексные файлы пакетов.

На клиенте информация о репозиториях хранится:
- В файле `/etc/apt/sources.list`
- В файлах каталога `/etc/apt/sources.list.d/`

Существует два формата записи о репозитории:
- Старый **one-line** формат
- Новый формат (deb822 format)

Независимо от формата, для скачивания пакета `apt` необходимо знать:
- `type`
- `uri`
- `suite`
- `component`
- `arch`
После этого `apt` может составить полный путь вида:
`repo/dists/<suite>/<component>/binary-<arch>/Packages`

## Опции репозиториев
#### Types
Тип хранимых файлов. Доступно две опции:
- `deb` – бинарные файлы
- `deb-src` – исходники
#### URIs
URI репозитория. Обычно `http`, но иногда может встречаться `https` или `file`. Если протокол другой, то важно помнить про порт
Несмотря на название, в поле можно указать только один URI.
#### Suites
Обычно – ветка/версия дистрибутива.
Примеры на релизе `ubuntu noble`:
- `noble` – пакеты на релизе
- `noble-updates` – исправления/обновления после релиза
- `noble-security` – исправления безопасности после релиза
- `noble-backports` – новые версии программ, портированные под старую версию

Также это могут быть алиасы, вроде:
- `stable`
- `unstable`
- `testing`
Они меняются разово. Несмотря на название, указывать `stable` может быть опасно, так как одномоментно `stable` версией может стать новый релиз и гора пакетов пойдёт разово обновляться.
#### Components
По сути – раздел пакетов. Пакеты делят в соответствии с лицензиями и правами.
Пример для Ubuntu:
- `main`  
- `universe`  
- `restricted`  
- `multiverse`
#### Signed-By
Пусть до GPG ключа, которым можно подтвердить подлинность репозитория. Это публичный ключ, который распространяется свободно.
Можно добавить репозиторий в доверенный (`trusted=true`). Тогда проверка ключом будет необязательна.
#### Architecture
Архитектура пакета. Опционально, так как используется архитектура текущей машины.
Примеры опций:
- `arm64`
- `amd64`
Можно указывать несколько.


## 1. Новый формат (deb822 format)

Примерный вид:
```yml
Types: deb
URIs: http://archive.ubuntu.com/ubuntu
Suites: noble
Components: main universe
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

Types: deb
URIs: http://archive.ubuntu.com/ubuntu
Suites: noble-updates
Components: main universe
Trusted: yes # Used instead of Signed-By
```
В одном файле может быть несколько записей. Их надо разделить пустой строкой.

## 2. Старый формат (one-line format)
Одна строка – одна запись о репозитории.
Формат строки:
```
Type [Options] URI Suite Component1 Component2
```
- Квадратные скобки с опциями могут быть пропущены.
- Нельзя писать несколько `Suite` или `Type` в одной строке (надо несколько строк)

Возможные опции:
- `signed-by` – путь к GPG-ключу
- `trusted` – не проверять подлинность
- `arch` – архитектура

Полный пример:
```
deb [arch=amd64 signed-by=/usr/share/keyrings/docker.gpg] \  
https://download.docker.com/linux/ubuntu noble stable
```

Преобразовать старый формат к новому можно автоматически:
```bash
apt modernize-sources
```
