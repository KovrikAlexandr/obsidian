## Введение

**Тема** – пайплайн записи логов в систему мониторинга.
#### **Цель работы**

Исследовать характеристики многоканальной системы массового обслуживания с ожиданием (M/M/n/∞) с использованием методов математического моделирования и анализа.
#### **Реальный процесс**

1. Клиент пишет JSON лог (обязательные поля: **timestamp** – время, group – группа это логическая единица в тенанте, **system** – имя сервиса в группе, **level** (`INFO`, `WARNING`, `ERROR`) – вид лога) в **Logs Collector** по REST API (возможна запись как одной json строки, так и батча)

2. **Logs Collector**, приняв лог по REST API, пишет его как событие в один из брокеров **Kafka**

3. Из **Kafka** логи вычитывает сервис **Fury**. Он поднимает N потоков-воркеров в зависимости от количества групп и их квот (этот момент мы вряд ли будем использовать в модели)

4. **Fury** валидирует JSON строку (есть все обязательные поля) и записывает лог в кластер **Opensearch**

Для лабораторной работы я упростил реальный процесс до такого:

- Есть поток логов (событий) из **Kafka**;

- Поток обрабатывается **n** воркер-процессами (каналами обработки) **Fury**;

- λ — интенсивность логов из **Kafka**;

- μ — интенсивность обработки логов одним воркером;

- n — число воркеров;

- Очередь — **Kafka** (считаем бесконечной);
#### **Задачи**

Для разных значений количества каналов (n) и интенсивности обслуживания (μ):

- Расчитать следующие показатели:
	
	- Вероятность простоя системы (все каналы свободны);
	
	- Вероятность того, что заявка будет ждать в очереди;
	
	- Среднее число заявок в очереди;
	
	- Среднее время ожидания заявки в очереди;
	
	- Среднее время пребывания заявки в системе;
	
	- Коэффициент загрузки системы;
	
- Постройте графики:
	
	- Зависимости среднего времени ожидания от количества каналов;
	
	- Средней длины очереди от количества каналов;
    
- Проанализировать влияние значений количества каналов (n) и интенсивности обслуживания (μ) на конечные характеристики системы.

## Модель

Реальный процесс я упростил до такого:

- Есть поток логов из **Kafka**;

- Поток обрабатывается N консьюмерами – воркер-процессами **Fury**;

#### **Входные параметры модели**

Входными параметрами системы будут:

- μ — интенсивность обработки логов одним воркером;

- n — число воркеров;

- t – время моделирования;

λ (интенсивность логов из **Kafka**) возьмём как постоянную величину λ = 100 логов/сек

#### **Основные понятия в системе**

- **Событие** – лог (одна JSON строка);

- **Канал обработки** – воркер-процесс **Fury**;

- **Нагрузка** – сколько приходит логов из **Kafka** по отношению к скорости обработки:
$$  
\rho = \frac{\lambda}{n \mu}  
$$
> ρ < 1 – система справляется;
> ρ ≈ 1 – почти перегружена;
> ρ > 1 – очередь растёт бесконечно;

- **Загрузка** – доля времени, когда воркер-процессы заняты:
$$
загрузка = \rho
$$
> По сути то же самое, что и **нагрузка**, но отличается интерпретация

- **Вероятность простоя** – вероятность, что в момент времени в системе нет заявок (все воркеры свободны):  
$$  
P_0 = \left( \sum_{k=0}^{n-1} \frac{(\lambda/\mu)^k}{k!} + \frac{(\lambda/\mu)^n}{n! \cdot (1 - \rho)} \right)^{-1}  
$$

- **Производительность** – сколько логов реально записывается в **OpenSearch**:  
$$  
A = \lambda  
$$

> В системе M/M/n/∞ нет потерь, поэтому производительность равна интенсивности входного потока (мы обработаем все заявки)

- **Интенсивность необслуженных** – с какой интенсивностью заявки теряются:  
$$  
\lambda_{\text{loss}} = 0  
$$

> В данной модели очередь бесконечная, поэтому отказов не будет

- **Среднее время пребывания в системе** – среднее время от попадания лога в Kafka до записи в **OpenSearch**:  
$$  
W = \frac{L}{\lambda}  
$$

> Формула Литтла
> L — среднее число логов в системе (в очереди + в обработке)  
> Чем больше очередь, тем больше время пребывания

### Выведение формул

В системе массового обслуживания типа M/M/n/∞:

- заявки поступают по пуассоновскому потоку с интенсивностью ( $\lambda$ );

- время обслуживания одной заявки имеет экспоненциальное распределение с параметром ( $\mu$ );

- система содержит ( n ) каналов обслуживания;

- очередь не ограничена.


Коэффициент загрузки системы определяется как:
$$
\rho = \frac{\lambda}{n\mu}  
$$

Для существования стационарного режима необходимо выполнение условия равновесия:

$$\rho < 1  $$
#### Процессы гибели и размножения

Состояние системы определяется числом заявок ( k ) в системе. Переходы между состояниями происходят следующим образом:

- ( k -> k+1 ) — поступление новой заявки с интенсивностью ( $\lambda$ );

- ( k -> k-1 ) — завершение обслуживания с интенсивностью, зависящей от числа занятых каналов.

Таким образом, рассматриваемая модель является частным случаем процесса гибели и размножения.
#### Одноканальная система

Для одноканальной системы M/M/1 интенсивность обслуживания равна ( $\mu$ ), и для стационарных вероятностей выполняется соотношение:

$$P_{k+1} = \rho P_k, \quad \rho = \frac{\lambda}{\mu}  $$

Отсюда следует:

$$P_k = \rho^k P_0  $$

Таким образом, вероятности состояний образуют геометрическую прогрессию. Сходимость суммы вероятностей требует выполнения условия ( $\rho$ < 1 ).
#### Многоканальная система

В многоканальной системе интенсивность обслуживания зависит от числа заявок:

- при $( k < n ): ( k\mu )$;

- при $( k \ge n ): ( n\mu )$.

После того как все каналы заняты, система работает с постоянной интенсивностью обслуживания. В этом случае отношение вероятностей соседних состояний становится постоянным:

$$P_{k+1} = \rho P_k, \quad \rho = \frac{\lambda}{n\mu}$$

Отсюда для ( $k \ge n$ ):

$$P_k = P_n \rho^{k-n}$$
#### Вероятность простоя

Вероятность того, что в системе нет заявок (все каналы свободны), определяется как:

$$P_0 =  
\left(  
\sum_{k=0}^{n-1} \frac{a^k}{k!}  
+  
\frac{a^n}{n!(1-\rho)}  
\right)^{-1}  
$$
где:
$$a = \frac{\lambda}{\mu}  $$
#### Средняя длина очереди

Очередь формируется только в состояниях ( k > n ). Средняя длина очереди определяется как:
$$L_q = \frac{P_{\text{wait}} \cdot \rho}{1 - \rho}$$

где ( $P_{\text{wait}}$ ) — вероятность того, что заявка будет ожидать обслуживания (формула Эрланга)

#### Среднее число заявок в системе

Общее число заявок в системе складывается из заявок в очереди и заявок в обслуживании:

$$
L = L_q + \frac{\lambda}{\mu}  
$$

где:

- ($L_q$ ) — средняя длина очереди;

- ( $\lambda/\mu$ ) — среднее число заявок, находящихся в обслуживании.

## Анализ результатов

Средняя длина очереди определяется формулой:

$$L_q = \frac{P_{\text{wait}}\rho}{1-\rho}$$

где ($P_{\text{wait}}$) — вероятность ожидания, вычисляемая по формуле Эрланга. При увеличении числа каналов (n) или интенсивности обслуживания ($\mu$) коэффициент загрузки

$$\rho = \frac{\lambda}{n\mu}$$

уменьшается. Это приводит к снижению вероятности ожидания ($P_{\text{wait}}$) и увеличению знаменателя ($1-\rho$). Поэтому средняя длина очереди быстро убывает и график похож на гиперболу.

Среднее время ожидания определяется формулой:
$$W_q = \frac{L_q}{\lambda}$$

Поскольку ($\lambda$) фиксирована, график ($W_q$) повторяет форму графика ($L_q$), отличаясь только масштабом по вертикали.
